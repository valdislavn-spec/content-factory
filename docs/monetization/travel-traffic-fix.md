# Travelpayouts: почему трафик плохой и что исправлено (09.11.2026)

## Диагноз

Статистика 02–09.11: **7 показов, 250 кликов, 0 броней, $0**. Показов меньше,
чем кликов, — значит клики идут не от реальных людей, а от ботов/превью
(автообход ссылок, сканеры, тесты). Для партнёрской сети это выглядит как
мусорный трафик: CR 0%, eCPC $0, риск санкций.

## Что исправлено

1. **Бот-фильтр в трекере.** `/r/{code}` больше не отдаёт 302 на партнёрку.
   Вместо этого — HTML-интерстишиал: переход по партнёрской ссылке и счёт клика
   выполняются только через JavaScript (`/c/{code}`), который боты не
   исполняют. HEAD-запросы получают 200 без Location. Итог: в Travelpayouts
   попадают только реальные браузеры, клики в нашей статистике — только люди.
2. **Реальные авиа-офферы вместо generic-рекламы.** Travel-пост теперь берёт
   дешёвый билет из Travelpayouts prices API (`/v2/prices/latest`) и публикует
   цену/маршрут/даты, например «Miami → BWI from $74 round trip · Dec 23–31»,
   с deep-ссылкой на поиск Aviasales (marker 674170) через трекер
   (`travel-deal` обновляется перед публикацией).
3. **Ротация.** Реклама — 1 из 4 постов (4 поста/сутки), цена и маршрут
   меняются каждый раз, карточка генерируется с ценой.
4. **Существующий flights digest** (параллельная работа): ежедневная страница
   `docs/flights/` с дешёвыми билетами и IndexNow/SEO — дополнительный канал
   реального трафика.

## Что дальше

- Дать накопиться 3–7 дням реальных кликов, смотреть CR по SubID/стране в
  Travelpayouts.
- Подключить реальные каналы с аудиторией (Telegram), а не только Fediverse:
  основной объём кликов должен идти оттуда.
- Проверить качество трафика в кабинете: после фильтра ботов клики должны
  упасть в разы, а бронирования — появиться.
