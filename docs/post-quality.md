# Качество постов: детерминированная рубрика и гейт

Модуль `content_factory/nlp/quality.py` оценивает готовый текстовый пост
(Telegram-канал, RU/EN/ES) по фиксированному набору правил. Оценка полностью
детерминированная: никакой сети, никаких LLM, никаких случайных чисел — один и
тот же пост всегда получает один и тот же балл и один и тот же список проблем.
Поэтому рубрику можно использовать в тестах, в CI и в гейте публикации.

Зачем это нужно:

- видеть качество поста числом (`0..100`) и отслеживать его в метаданных
  публикации;
- ловить проблемы, которые старые проверки конвейера не видели: кликбейт,
  капс, повторы, отсутствие CTA/хэштегов, слабый хук, утечки markdown;
- при желании — не публиковать посты ниже порога (opt-in, по умолчанию выключено).

## 1. Быстрый старт

```python
from content_factory.config import Settings
from content_factory.models import GeneratedPost
from content_factory.nlp.quality import score_post

settings = Settings.load(load_env=False)

report = score_post(post, channel, settings)   # post — GeneratedPost или строка
report.score                 # 0..100, целое
report.blockers              # list[QualityIssue] — публиковать нельзя
report.warnings              # list[QualityIssue] — предупреждения
report.metrics               # dict с измерениями текста
report.as_dict()             # JSON-совместимое представление
```

`score_post(post, channel, settings)` принимает:

- `post` — `GeneratedPost` (или объект/словарь с `text`, `sources`,
  `hashtags`, `format`) либо готовая строка текста. Для строки проверка
  «нет источников» пропускается: у строки нет списка источников;
- `channel` — `ChannelConfig` (лимит символов, флаг эмодзи, CTA, язык);
- `settings` — `Settings` (берутся `pipeline.min_post_chars`,
  `pipeline.post_mode`, `pipeline.cta`); можно передать `None`.

## 2. Откуда берётся балл

`score = clamp(100 - сумма штрафов, 0, 100)`. Каждая проблема несёт штраф в
баллах (таблица ниже). Проблемы уровня **blocker** — причина не публиковать
пост (это же поведение у старых проверок конвейера); **major**/**minor** —
предупреждения: балл снижают, но сами по себе не блокируют.

## 3. Таблица рубрики

Измерения и коды (в скобках — severity: `B` blocker, `M` major, `m` minor):

| Измерение | Код | Штраф | Что проверяет |
|---|---|---|---|
| Текст | `empty_text` | 100 B | пост пустой |
| Длина | `too_short` | 35 B | плейн-текст короче `pipeline.min_post_chars` (для digest-режима порог может быть 140) |
| Длина | `too_long` | 35 B | текст длиннее `max_post_chars * 1.35` |
| Длина | `over_limit` | 8 M | текст длиннее `max_post_chars`, но в пределах допуска 1.35× |
| Структура | `no_structure` | 8 M | весь текст одним блоком, нет абзацев |
| Структура | `long_paragraph` | 3 m | абзац длиннее 700 символов |
| Хук | `weak_hook` | 6 M | первая строка длиннее 120 символов или заглушка «Новость/News/Noticia» |
| Хук | `hook_long` | 3 m | первая строка длиннее 90 символов (цель ≤ 90) |
| Хук | `hook_ellipsis` | 2 m | хук обрезан многоточием |
| Хук | `hook_echo` | 5 M | первое предложение лида повторяет заголовок |
| HTML | `broken_html` | 30 B | несбалансированные теги / невалидный Telegram-HTML |
| HTML | `unsupported_tags` | 6 M | теги вне `b/i/a/code/u/s/blockquote/pre/em/strong/br` |
| HTML | `stray_angles` | 3 m | «сырые» `<`/`>` в тексте (не экранированы) |
| HTML | `bad_entities` | 2 m | битые HTML-сущности (`&` без `;`) |
| Ссылки | `no_sources` | 25 B | у поста нет источников |
| Ссылки | `missing_source_links` | 10 M | источники есть, но в тексте нет HTML-ссылок |
| Ссылки | `plain_url` | 20 B | в тексте «голый» URL вместо `<a href=…>` |
| Ссылки | `bad_link_scheme` | 3 m | ссылка не `http(s)://`, не `tg://`, не `mailto:` |
| Ссылки | `link_spam` | 2 m | больше 8 ссылок |
| Хэштеги | `hashtags_missing` | 8 M | 0 хэштегов |
| Хэштеги | `hashtags_low` | 3 m | 1 хэштег (нужно 2–5) |
| Хэштеги | `hashtags_high` | 2–10 m/M | больше 5 (от 9+ — major) |
| Хэштеги | `hashtags_duplicate` | 2 m | повторяющиеся хэштеги |
| CTA | `cta_missing` | 8 M / 3 m | нет CTA канала (major, если CTA настроен в канале/настройках; minor, если CTA не настроен и нет узнаваемого призыва) |
| Повторы | `duplicate_sentences` | 8 M | повторяющиеся предложения (Jaccard ≥ 0.85) |
| Тон | `all_caps` | 10 M / 3 m | капс-крик (≥ 2 слов заглавными и ≥ 8% текста) |
| Тон | `clickbait` | до 24 M | кликбейт-фразы RU/EN/ES (10 за фразу, максимум 24) |
| Тон | `punctuation_shout` | 3 m | `!!!`/`???` |
| Читабельность | `readability` | 6 M / 3 m | средняя длина предложения > 30 / > 24 слов |
| Читабельность | `long_sentence` | 3 m | предложение длиннее 45 слов |
| Читабельность | `no_sentence_breaks` | 6 M | длинный текст без знаков конца предложения |
| Факты | `fact_density` | 6 M / 3 m | меньше 1.0 / 2.5 фактов (цифры, даты, организации) на 1000 символов |
| Факты | `weak_fact_style` | 3 m | цифры поданы служебной строкой («Фигурирующие цифры: …», «The figures involved: …») |
| Markup | `markdown_leak` | 10 M | `**…**`, `__…__`, ``` ``` ```, `##`, `[текст](url)` |
| Markup | `placeholder_text` | 40 B | `{{…}}`, `TODO`, `undefined`, `lorem ipsum` |
| Эмодзи | `emoji_policy` | 1–6 m/M | эмодзи в канале с `emoji: false` (M), больше 8/12 эмодзи (m/M), ноль эмодзи в канале с эмодзи (m) |

Полные пороги — константы в начале `content_factory/nlp/quality.py`
(`HOOK_TARGET`, `HASHTAG_MIN/MAX`, `FACT_DENSITY_*`, ...); они зафиксированы,
чтобы балл был воспроизводим.

## 4. Примеры

### Хороший пост (детерминированный генератор, RU)

```text
🤖 OpenAI представила новую модель GPT-5

Компания сообщила, что модель доступна разработчикам через API уже с 18 октября.
Новая модель поддерживает контекст до 200 тысяч токенов.

По данным бенчмарков, качество ответов выросло на 25% по сравнению с предыдущей версией.

Источники: Habr · CNews · 3DNews
Больше разборов — в нашем канале.
#технологии #ИИ #OpenAI #GPT5
```

`score_post(...).score == 100`, блокеров и предупреждений нет: хук короткий,
абзацы на месте, цифры и даты есть, источники оформлены HTML-ссылками,
хэштегов 4, CTA на месте, кликбейта/капса/markdown нет.

### Плохой пост (фикстура для тестов)

```text
СРОЧНО!!! ШОК!!! Вы не поверите: рынок рухнул. ПОДПИСЫВАЙТЕСЬ!!!
```

`score == 0`: блокеры `too_short` и `no_sources`, плюс предупреждения
`clickbait`, `all_caps`, `hashtags_missing`, `cta_missing`,
`punctuation_shout`, `no_structure`.

### Пограничный пост (пример срабатывания гейта)

```text
СРОЧНО: ВСЁ РУХНУЛО

Ситуация на рынке изменилась. Ситуация на рынке изменилась. Вы не поверите, но
это просто шок. ... <a href="https://example.com">Habr</a>
```

Старые проверки конвейера такой пост пропускают (длина и ссылки в порядке), но
рубрика ставит `46`: кликбейт, капс, повторы, нет хэштегов и CTA, нет
конкретных фактов. С включённым гейтом пост отклоняется.

## 5. Какие фикстуры улучшились

Оценки получены одной и той же рубрикой на постах, сгенерированных
детерминированным генератором до (коммит-снимок) и после улучшений
`content_factory/nlp/generator.py`; входные кластеры одинаковые.

| Фикстура | Было | Стало | Что исправлено |
|---|---|---|---|
| RU story «OpenAI представила новую модель GPT-5» | 84 | 100 | лид перестал дословно повторять заголовок (`hook_echo`, `duplicate_sentences`), цифра 25% подана фактом, а не строкой «Фигурирующие цифры» (`weak_fact_style`) |
| RU analysis (тот же кластер) | 87 | 100 | лид не дублирует заголовок (`hook_echo`, `duplicate_sentences`) |
| EN story «OpenAI introduced its new GPT-5 model» | 97 | 100 | цифры поданы предложением из источника, а не «The figures involved» (`weak_fact_style`) |
| ES story «El Gobierno de España aprueba…» | 92 | 100 | лид без эха заголовка + цифры фактом |
| RU digest из 2 новостей | 100 | 100 | без изменений — гейт проходит |

Для калибровки: «пограничный» пост из примера ниже получает 46 (гейт
отклоняет при `min_score: 60`), «плохой» пост-фикстура — 0.

## 6. Гейт публикации (opt-in)

По умолчанию гейт **выключен**: `quality_issues()` возвращает ровно те же
блокеры, что и раньше, а рубрика только складывает метрики в `post.meta`.
Включается в `config/settings.yaml` (ключ намеренно не добавлен в репозиторий,
чтобы поведение по умолчанию не менялось):

```yaml
pipeline:
  # false / нет ключа — только метрики в post.meta (по умолчанию)
  quality_gate: false
  # минимальный балл; используется, если quality_gate включён
  quality_gate_min_score: 60
```

Допустимые значения `quality_gate`:

| Значение | Поведение |
|---|---|
| `false` / нет ключа / `"off"` | гейт выключен, старые проверки не меняются |
| `true` | включён: блокируются blocker-проблемы рубрики и балл ниже `quality_gate_min_score` (по умолчанию 60) |
| число | включён с этим минимальным баллом (например `quality_gate: 75`) |
| `"warn"` | включён «мягко»: пишет предупреждения в meta, но не отклоняет посты |
| словарь | тонкая настройка: `{enabled, min_score, block_blockers, block_majors, warn_only}` |

Пример словаря:

```yaml
pipeline:
  quality_gate:
    enabled: true
    min_score: 70        # 0 = не проверять балл, только блокеры
    block_blockers: true # блокировать `broken_html`, `no_sources`, …
    block_majors: false  # true = блокировать и major-предупреждения
    warn_only: false     # true = только писать в meta, не отклонять
```

Когда гейт отклоняет пост, в списке причин появляются строки вида:

```text
quality[broken_html]: невалидный или несбалансированный HTML
quality score: 46 < 60
```

Чтобы не дублировать старые проверки, блокеры рубрики, которые уже нашли
`quality_issues()` (короткий текст, длинный текст, нет источников, голый URL),
в список повторно не добавляются.

## 7. Как читать метрики

После каждого вызова `pipeline.quality_issues()` в `post.meta` появляются:

| Ключ | Что внутри |
|---|---|
| `quality_score` | целое 0..100 |
| `quality_issues` | list[str]: blocker-сообщения рубрики, добавленные к старым проверкам |
| `quality_blockers` | list[dict]: блокеры рубрики (`code`, `severity`, `message`, `penalty`, `dimension`) |
| `quality_warnings` | list[dict]: все не-блокирующие проблемы с кодами и штрафами |
| `quality_metrics` | измерения текста: длина, абзацы, хук, ссылки, хэштеги, факты, кликбейт, эмодзи и т.д. |
| `quality_report` | полный JSON-совместимый отчёт (`score`, `issues`, `metrics`) |

Пример для хорошего RU-поста (фрагмент):

```json
{
  "quality_score": 100,
  "quality_warnings": [],
  "quality_metrics": {
    "plain_chars": 460,
    "paragraphs": 8,
    "hook_chars": 37,
    "hashtags": 4,
    "cta_present": true,
    "facts": 9,
    "fact_density": 19.57,
    "clickbait_hits": 0,
    "emoji": 2,
    "html_balanced": true
  }
}
```

`fact_density` — число фактов (цифры, даты, организации) на 1000 символов
плейн-текста. `hook_chars` — длина первой строки (без ведущих эмодзи).
`quality_metrics` всегда JSON-сериализуем, его можно складывать в отчёты и
логи без дополнительной обработки.

## 8. Ограничения

- Рубрика — эвристики, а не семантическая оценка: она не понимает смысл текста,
  поэтому задачи вроде «факт верен/выдуман» решает валидация LLM-ответов в
  генераторе, а не этот модуль.
- Кликбейт-списки (RU/EN/ES) намеренно узкие: только явные маркеры, чтобы не
  штрафовать обычные новостные формулировки.
- «Организации» считаются по словарным маркерам (`Bank`, `Ministry`,
  `компания`, `министерство`, …) — это приближение, но детерминированное.
- Балл не заменяет старые блокеры: по умолчанию публикация отклоняется только
  по прежним правилам, рубрика — метрики + opt-in гейт.

## 9. Где код и тесты

- `content_factory/nlp/quality.py` — рубрика (`QualityIssue`, `QualityReport`,
  `score_post`).
- `content_factory/pipeline.py` — `quality_issues()`: метрики в `post.meta` и
  опциональный гейт.
- `content_factory/nlp/generator.py` — детерминированные правила структуры
  (лид без эха заголовка, факты с цифрами, добор хэштегов) и правила качества
  в LLM-промптах RU/EN/ES.
- `tests/test_post_quality.py` — коды рубрики, монотонность, фикстуры
  (good ≥ 80, bad < 50), гейт и интеграция в `generate_posts`.
