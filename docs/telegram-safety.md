# Безопасность Telegram-аккаунта и бота

Дата: 09.11.2026. Цель — чтобы аккаунт владельца и каналы не попали под ограничения
Telegram из-за автоматизации/монетизации.

## Что мы делали и почему это легально

| Действие | Риск | Почему безопасно |
|---|---|---|
| Постинг через **официальный Bot API** (наш бот — админ каналов) | нет | это штатный способ публикации; лимиты 1 пост/90 мин на канал, без массовых рассылок |
| Пин/редактирование закрепов через Bot API | нет | бот — админ своего канала |
| Вход в AdminHub через **официальный Telegram OIDC** (`oauth.telegram.org`) | низкий | штатный вход «Log in with Telegram», scope только профиль/боты |
| Добавление бота в канал по **официальной ссылке** `t.me/<bot>?startchannel&admin=...` | нет | стандартный Telegram-флоу добавления админа |
| Партнёрские посты в **своих** каналах | низкий | свои каналы, маркировка «реклама», лимит 1:5, без обещаний доходности |
| Чтение метрик канала через Telethon (опционально) | низкий | read-only, без вступлений/сообщений/комментариев |

## Чего мы НЕ делаем (это реально ведёт к бану)

- ❌ userbot-автоматизация: массовые сообщения, комментарии, вступления, парсинг через
  пользовательский аккаунт;
- ❌ накрутка подписчиков/просмотров/реакций, «массфолловинг», фейковые giveaway;
- ❌ рассылки партнёрских ссылок по чужим каналам/чатам и спам в комментариях;
- ❌ мультиаккаунты для рефералок и эмуляция подписок;
- ❌ обещания гарантированного дохода, «сигналы», скам-офферы — это нарушение ToS и
  риск ограничений канала.

## Что сделать вам для аккаунта (5 минут)

1. **Включить 2FA**: Telegram → Settings → Privacy & Security → Two-Step Verification.
2. **Проверить сессии**: Settings → Devices → завершить незнакомые. После настройки
   AdminHub можно завершить сессию «Telegram Login» (если появится в списке).
3. **Проверить статус аккаунта**: написать `@SpamBot` → `/start` — он покажет, есть ли
   ограничения (обычно «no limits»).
4. **Не входить в Telegram-аккаунт через публичные VPN-ноды** из этой настройки: публичная
   нода видит домены и IP-историю. Используйте её для браузинга, а аккаунт-логины — с
   домашнего IP/своего VPS. Один OIDC-вход в AdminHub уже сделан — этого достаточно.
5. **Не давать токен бота третьим лицам без необходимости**: AdminHub его уже получил для
   публикации кросс-постов. Если хотите минимизировать риск — создайте отдельного бота
   через @BotFather, добавьте его админом только в 1–3 канала и переподключите в AdminHub;
   после этого можно перевыпустить токен основного бота.
6. **Не платить «разблокировщикам»** и не переходить по ссылкам «ваш аккаунт будет удалён»
   — это фишинг.

## Если появилось ограничение

1. Не паниковать: большинство ограничений (спам-блок, запрет писать незнакомым) снимаются
   автоматически или через `@SpamBot`.
2. Написать `@SpamBot` → `/start` → «This message is not spam» / оспорить.
3. Обратиться в поддержку Telegram (Settings → Help) с описанием: «канал/бот, публикация
   контента, автоматизация только через официальный Bot API».
4. Не создавать новые аккаунты для обхода — это усугубляет.

## Контроль

```bash
# локально (через VPN): проверка прав бота, частоты постов, раскрытия, сессий
./.venv/bin/python scripts/tg_safety_check.py
./.venv/bin/python scripts/tg_safety_check.py --json
```

Проверять раз в неделю или после изменения прав/подключения новых сервисов.
Скрипт ничего не меняет — только читает и предупреждает.
