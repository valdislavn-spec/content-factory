# Добровольная поддержка проекта (не paywall)

Монетизация только на добровольной основе: посты остаются бесплатными, доступ
никому не закрывается. В пост добавляется одна необязательная строка с
donate/tip-ссылкой (Tribute-донат, Boosty-донат, DonationAlerts и т.п.).
Никакого платного контента и «подписки ради чтения» этот слой не делает.

## Как включить

1. Создай страницу добровольных донатов:
   - **Tribute** — «донат»/«поддержка» отдельно от платных подписок;
   - **Boosty** — донат/разовая поддержка;
   - **DonationAlerts** — донат-страница.
2. Вставь ссылку в [`config/support.yaml`](../config/support.yaml):

```yaml
enabled: true
mode: voluntary
url: "https://tribute.tg/.../donate"
channels: []          # пусто = все; ["crypto-news"] — только выбранные
frequency: 1           # 1 = каждый пост; 2/3 = реже (детерминированно)
```

Либо задай `SUPPORT_URL` в `.env`/секретах CI — env важнее файла.
В GitHub Actions удобнее Repository variable `SUPPORT_URL`
(Settings → Secrets and variables → Actions → Variables): workflow передаёт её
в env, ничего коммитить не нужно — следующий тик подхватит ссылку.

3. Проверь:

```bash
./.venv/bin/python scripts/unified.py doctor     # пункт «добровольная поддержка»
./.venv/bin/python scripts/support_links.py      # UTM-ссылки по каналам
```

## Что появится в посте

Пример (EN-канал):

```
❤️ Support the project voluntarily: here
```

- Текст подставляется по языку канала (`ru`/`en`/`es`), можно переопределить
  `text_ru/text_en/text_es` и `link_label_*`.
- Блок необязательный: при нехватке места (лимит длины) он отбрасывается
  вместе с CTA, контент не ломается.
- Ссылка не ставится, если `url` пуст или `enabled: false`.
- Ничего не блокируется и не проверяется: это именно донат, а не доступ.

## UTM и учёт переходов

К donate-ссылке автоматически добавляются:

```
utm_source=telegram
utm_medium=post
utm_campaign=voluntary_support
utm_content=<id канала>
utm_term=<язык>
```

Переопределение — в секции `utm`:

```yaml
utm:
  source: telegram
  medium: post
  campaign: voluntary_support
```

- `scripts/support_links.py` показывает готовые ссылки для каждого канала и
  сохраняет `data/support_links.json`.
- Переходы и конверсии смотри в аналитике площадки донатов (Tribute/Boosty/
  DonationAlerts поддерживают UTM) или в Яндекс Метрике/GA4, если ведёшь на
  лендинг.
- Для точного счётчика кликов нужен внешний redirect/шортлинк с статистикой;
  текущая реализация даёт корректную UTM-атрибуцию без внешних сервисов.

## Частота и каналы

- `frequency: 1` — каждый пост.
- `frequency: 2` или `3` — блок появляется детерминированно реже (по каналу и
  заголовку поста), без состояния и без дублей.
- `channels: ["crypto-news", "ai-news"]` — только в этих каналах.

## Налоги и ограничения

- Добровольный донат — всё равно доход: физлицо декларирует НДФЛ (3-НДФЛ),
  самозанятый — НПД 4/6%. Площадка может не быть налоговым агентом.
- Если за донат даётся закрытый контент/привилегия — это уже вознаграждение,
  а не подарок; схему лучше проверить с бухгалтером.
- Не используй этот блок для продажи инвест-рекомендаций — отдельные
  регуляторные риски.

## Выключить

```yaml
enabled: false
```

или очисти `url`, или убери `SUPPORT_URL`. Посты вернутся к прежнему виду.
