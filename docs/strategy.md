# Стратегия публикаций (пик/день/ночь)

Внедрены самые полезные пункты внешней стратегии для 6 каналов + правила
заказчика. Визуал (HTML, эмодзи, карточки) остаётся за пайплайном, а
текст/расписание оптимизированы под пиковое время.

## Расписание (локальное время канала)

| Режим | Каденция | Что публикуем |
|---|---|---|
| **Пик** (US: 07–09, 12–13, 17–20; LatAm: 07–09, 12–14, 19–21) | каждый час | обычный пост, но **начинается с трендов** |
| **День** (остальное 07:00–23:00) | ~100 минут (90–105) | микс форматов 30/40/30 |
| **Ночь** (23:00–07:00) | каждые 140 минут | короткий дайджест (≤900 симв.) |

Часовой пояс каналов: US-ветка — UTC-5 (Нью-Йорк), LatAm — UTC-6
(Мехико/Богота). Каналы внутри ветки сдвинуты на 0/10/20 и 0/15/30 минут,
чтобы посты не выходили одновременно (каскадная задержка 15–20 минут).

## Микс форматов днём (30% / 40% / 30%)

- **story (30%)** — новость: заголовок + 2–3 факта + источник;
- **analysis (40%)** — факт → контекст → вывод;
- **interactive (30%)** — факт/контекст + вопрос к аудитории (вовлечение).

Ночью — только `digest` (3–5 фактов, без «воды»), лимит `night_max_chars`.

## Тренды в начале поста (пиковые часы)

Источники (бесплатные, без ключей, с кэшем на 30 минут):
- **Google Trends RSS** (`geo=US` / `geo=MX`) — поисковые тренды;
- **CoinGecko Trending** — монеты, которые сейчас ищут (крипто-каналы);
- **GitHub Trending** — растущие репозитории (AI/tech-каналы);
- **Hacker News top** — повестка tech-сообщества;
- **локальная частота** терминов в свежих статьях канала — fallback.

Модуль: `content_factory/trends.py`; тренды попадают в `post.meta["trends"]`,
в начало поста и влияют на порядок сюжетов (трендовые первыми).

## Что не внедряли

- **pytrends** — архивирован (2024), Google блокирует; вместо него RSS.
- **JSON-метаданные для внешнего скрипта** — у нас свой пайплайн, метаданные
  пишутся в БД (`slot_mode`, `slot_local`, `max_chars_target`, `trends`).
- **Автоснижение ночной частоты по отпискам** — нет данных об отписках из
  Bot API; аналитика есть (`python -m content_factory report`), правило можно
  добавить позже.
