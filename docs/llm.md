# LLM и суммаризация

Контент-завод умеет работать **без нейросетей вообще** и при этом публиковать
осмысленные посты. Но при желании можно подключить бесплатную локальную LLM,
бесплатный лимит российского облачного API или зарубежный Dify Cloud. Этот
документ объясняет режимы, требования к железу и как проверить выбранный
вариант.

> Главное: **платить не обязательно.** Режим по умолчанию `extractive` не
> требует ни моделей, ни интернета, ни токенов.

## 1. Восемь режимов (`llm.provider`)

| Режим | Что использует | Интернет | Стоимость | Кому подходит |
|---|---|---|---|---|
| `extractive` | стандартная библиотека Python (TextRank + шаблоны) | нет | 0 ₽ | всем, по умолчанию; слабый ПК, сервер без GPU |
| `ollama` | локальная LLM через Ollama | нет | 0 ₽ | есть 8+ ГБ RAM; хотите более «живые» тексты |
| `openai_compatible` | llama.cpp / LM Studio / vLLM с OpenAI-совместимым API | нет | 0 ₽ | уже есть локальный сервер моделей |
| `gigachat` | GigaChat API (Сбер) | да | 0 ₽ в пределах лимита | аккаунт РФ, нужен стабильный доступ |
| `yandexgpt` | YandexGPT API | да | пробный грант | аккаунт Yandex Cloud |
| `dify` | приложение Dify (Cloud или self-hosted) через Service API | да | бесплатный лимит Dify Cloud, дальше по тарифу | нужен аккаунт Dify; хочется менять промпты и модели без кода |
| `cloudflare` | Cloudflare Workers AI (OpenAI-совместимый REST API) | да | free: 10 000 neurons/день, дальше $0.011 за 1 000 | аккаунт Cloudflare; нужен быстрый облачный LLM |
| `cohere` | Cohere API (OpenAI-совместимый Compatibility API) | да | trial: 1 000 запросов/мес; production — по тарифу | ключ Cohere; из РФ только через GitHub Actions/VPN |

Переключается в `config/settings.yaml`:

```yaml
llm:
  provider: cloudflare   # extractive | ollama | openai_compatible | gigachat | yandexgpt | dify | cloudflare | cohere
```

После изменения перезапустите процесс (`Ctrl+C` и снова `daemon`/`run`).

### 1.1. `extractive` (по умолчанию)

Работает так: из текста статей выбираются самые «весомые» предложения
(TextRank по совстречаемости слов), из них собирается резюме; факты, цифры и
тональность определяются шаблонами и словарями. Ничего не скачивается.

**Плюсы:** работает всегда, офлайн, 0 ₽, без RAM/GPU, детерминированно.
**Минусы:** текст ближе к «умному реферату», чем к авторскому посту; не
пересказывает своими словами; стиль зависит от исходников.

### 1.2. `ollama` — локальная бесплатная LLM

Ollama работает на том же компьютере (или домашнем сервере) и полностью
офлайн: ни ключей, ни аккаунтов, ни лимитов. Это основной бесплатный
«умный» режим завода — в `config/settings.yaml` он включён по умолчанию.

```bash
# 1) Запустить сервер (бинарник и модели лежат в data/ollama/, ключи не нужны):
bash scripts/start-ollama.sh start

# 2) Скачать модель один раз (~7.6 ГБ для 9B в квантовании Q4):
bash scripts/start-ollama.sh pull qwen3.5:9b

# 3) Проверить:
bash scripts/start-ollama.sh status
```

В `config/settings.yaml`:

```yaml
llm:
  provider: ollama
  timeout: 300            # генерация 9B на CPU — десятки секунд
  max_tokens: 500
  ollama:
    base_url: http://127.0.0.1:11434
    model: qwen3.5:9b
    num_ctx: 8192         # Ollama по умолчанию режет контекст до 4K, статьи — до 15k символов
    think: false          # reasoning-модели «думают» — для постов это лишние минуты
```

Модель должна быть уже скачана — Ollama не тянет её «на лету» в рамках
запроса, вернёт ошибку, если модели нет. Список скачанных моделей:
`bash scripts/start-ollama.sh status` (`ollama list`).

**Плюсы:** бесплатно, офлайн, без лимитов и регистраций, хорошее качество
пересказа на русском, данные не уходят наружу.
**Минусы:** нужна RAM/VRAM; на слабом ноутбуке генерация 1 поста может
занимать десятки секунд; первый запрос после запуска — дольше (загрузка
модели в память); сервер нужно держать запущенным (автозапуск — см.
[setup.md](setup.md)).

### 1.3. `openai_compatible` — свой сервер моделей

Подходит, если у вас уже запущен llama.cpp (`llama-server`), LM Studio, vLLM,
Ollama в режиме OpenAI-совместимого API и т. п.

```yaml
llm:
  provider: openai_compatible
  openai_compatible:
    base_url: http://127.0.0.1:11434/v1   # адрес вашего сервера
    model: qwen3.5:9b
    api_key_env: OPENAI_COMPAT_API_KEY
```

Если сервер не требует ключ, переменную `OPENAI_COMPAT_API_KEY` можно не
заполнять. Ключ читается из окружения, в YAML его не пишут.

**Ollama Cloud** подключается так же — это обычный OpenAI-совместимый endpoint
`https://ollama.com/v1`, ключ берётся из [ollama.com/settings](https://ollama.com/settings)
в `OLLAMA_API_KEY`. В конфиге — именованный провайдер:

```yaml
llm:
  providers:
    ollama_cloud:
      base_url: https://ollama.com/v1
      api_key_env: OLLAMA_API_KEY
      model: gemma4:31b
```

На pay-as-you-go доступны открытые модели (`gemma4:31b`, `gpt-oss:20b/120b`,
`nemotron-3-nano`), «pro»-модели (`glm-5.3`, `mistral-large-4`, `deepseek-v4`)
отвечают `402` — им нужен Pro/кредиты.

**Плюсы:** любые локальные модели и квантования, полный офлайн.
**Минусы:** нужно самостоятельно поднять сервер и следить за ним.

### 1.4. `gigachat` — GigaChat API (Сбер)

Российский облачный API. Есть бесплатный лимит для физических лиц; нужен
аккаунт GigaChat API и `client_id`/`client_secret`.

1. Зарегистрируйтесь в GigaChat API (см. официальный портал Сбера для
   разработчиков).
2. Получите `client_id` и `client_secret`, соберите строку
   `base64(client_id:client_secret)`.
3. Пропишите её в `.env`:

```bash
GIGACHAT_CREDENTIALS=ваша_base64_строка
```

4. В `config/settings.yaml` включите режим:

```yaml
llm:
  provider: gigachat
  gigachat:
    model: GigaChat
    scope: GIGACHAT_API_PERS
```

**Плюсы:** не нужен мощный ПК, русский язык на хорошем уровне, бесплатный
лимит. **Минусы:** нужен интернет и аккаунт; лимит может закончиться — тогда
система откатится на extractive и продолжит публиковать.

### 1.5. `yandexgpt` — YandexGPT API

1. Аккаунт Yandex Cloud, каталог (folder), сервисный аккаунт с ролью на
   YandexGPT, API-ключ.
2. В `.env`:

```bash
YANDEXGPT_API_KEY=ваш_ключ
YANDEX_FOLDER_ID=ваш_folder_id
```

3. В настройках:

```yaml
llm:
  provider: yandexgpt
  yandexgpt:
    model: yandexgpt-lite/latest
```

**Плюсы:** быстро, русский язык, есть пробный грант.
**Минусы:** платно после гранта; нужен интернет; настройка сложнее, чем у
Ollama.

### 1.6. `dify` — приложение Dify как LLM

[Dify Cloud](https://cloud.dify.ai) (или self-hosted Dify) — конструктор
AI-приложений: внутри собирается чат-бот, агент или workflow с любой моделью,
промптами, базой знаний и инструментами. Контент-завод обращается к
**опубликованному приложению** по Service API: `POST /v1/chat-messages`
(Chatbot, Agent, Chatflow) или `POST /v1/completion-messages` (Text
Generator). Ответ читается как SSE-поток, поэтому SDK не нужен.

Зачем это заводу: один ключ Dify даёт доступ к моделям, которые неудобно
подключать напрямую, а промпт и параметры модели можно менять в веб-интерфейсе
Dify без правки кода и перезапуска фабрики.

Шаги настройки:

1. Зарегистрируйтесь на [cloud.dify.ai](https://cloud.dify.ai). У бесплатного
   тарифа есть лимиты — проверяйте актуальные условия в личном кабинете.
2. Создайте приложение. Проще всего **Chatbot** (Chat) или Chatflow; Agent
   тоже подходит. Для приложения **Text Generator** укажите
   `app_mode: completion`. Приложение типа **Workflow** не подходит: у него
   отдельный эндпоинт `/workflows/run` и обязательные входные переменные —
   для завода проще создать Chat-приложение.
3. Опубликуйте приложение и откройте в нём `API Access` → `API Key`. Ключ
   привязан к конкретному приложению, а не ко всему workspace.
4. Добавьте ключ в `.env`:

   ```bash
   DIFY_API_KEY=app-...
   ```

   Для self-hosted Dify задайте ещё `DIFY_BASE_URL`, например
   `DIFY_BASE_URL=http://127.0.0.1/v1`.

5. В `config/settings.yaml`:

   ```yaml
   llm:
     provider: dify
     timeout: 180        # агент может думать дольше обычной модели
     dify:
       base_url: https://api.dify.ai/v1
       app_mode: chat    # chat | completion
       api_key_env: DIFY_API_KEY
       user: content-factory
       include_system: true
   ```

6. Проверьте подключение: `./.venv/bin/python -m content_factory llm-test`.

Что важно знать:

- **Промпты.** Фабрика передаёт свои инструкции в текст запроса: `system`
  склеивается с промптом. Если всё уже зашито в приложении Dify, поставьте
  `include_system: false`, чтобы не дублировать.
- **Параметры модели.** `temperature` и `max_tokens` задаются в приложении
  Dify — аргументы `generate()` фабрики игнорируются.
- **Переменные приложения.** Если в приложении заданы input-переменные, их
  значения можно передать через `llm.dify.inputs` (словарь).
- **Диалоги.** Каждый вызов идёт без `conversation_id`, то есть новый диалог;
  история между постами не переносится.
- **Стриминг.** Ответ всегда запрашивается в streaming-режиме: Agent-приложения
  поддерживают только его, а blocking-запрос на Dify Cloud может оборваться на
  долгой генерации.
- **Язык ответа.** Приложение Dify задаёт его своей инструкцией: для
англоязычных каналов она должна требовать English (см.
[english.md](english.md)).

**Text Generator.** По умолчанию фабрика кладёт текст в переменную `query`.
  Если приложение принимает устаревшее поле `query` верхнего уровня, поставьте
  `query_input: ""`.

Плюсы: модели и промпты меняются в Dify без кода, видны логи запросов, можно
использовать RAG и инструменты приложения. Минусы: внешний сервис с лимитами
и собственным биллингом, нужен интернет и опубликованное приложение (черновик
workflow API не отдаёт), параметры модели не из фабрики.

### 1.7. `cloudflare` — Cloudflare Workers AI

Cloudflare Workers AI отдаёт OpenAI-совместимый endpoint к моделям на GPU
Cloudflare. Free-план — **10 000 neurons/день** (сброс в 00:00 UTC), этого
хватает примерно на 100–150 вызовов в сутки на модели
`@cf/mistralai/mistral-small-3.1-24b-instruct`. Сверх лимита — Workers Paid
($0.011 за 1 000 neurons) либо автоматический fallback на `ollama`/`extractive`.

Шаги настройки:

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com).
2. **My Profile → API Tokens → Create Token → Custom token**: права
   `Account → Workers AI → Read` (плюс `Account → Account Settings → Read`,
   чтобы читать список аккаунтов).
3. Скопируйте **Account ID** (правая панель на странице аккаунта) и сам токен
   (`cfut_…` или `cfat_…`) в `.env`:

   ```bash
   CLOUDFLARE_ACCOUNT_ID=...
   CLOUDFLARE_API_TOKEN=...
   ```

4. В `config/settings.yaml`:

   ```yaml
   llm:
     providers:
       cloudflare:
         base_url: https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/ai/v1
         api_key_env: CLOUDFLARE_API_TOKEN
         model: "@cf/mistralai/mistral-small-3.1-24b-instruct"
   ```

5. Проверьте подключение: `./.venv/bin/python -m content_factory llm-test`.

Что важно знать:

- **Лимит.** 10 000 neurons/день на free-плане; расход виден в поле
  `usage.neurons` ответа и в дашборде Workers AI. Если лимит кончился, запросы
  падают, и фабрика уходит на следующий провайдер из `llm.fallback`.
- **Reasoning-модели.** `qwen3`, `glm`, `gemma`, `gpt-oss` и подобные могут
  вернуть пустой `content`: весь `max_tokens` уходит на «размышления». Для
  фабрики берите instruct-модель без reasoning — `mistral-small-3.1-24b`
  (хороший русский) или `@cf/meta/llama-3.1-8b-instruct-fp8` (в ~2 раза
  дешевле, но суше).
- **Платные модели.** Часть моделей (например, `deepseek-v4-flash`) на
  free-плане вернёт `not available on the Workers Free plan`.
- **Сеть.** `api.cloudflare.com` доступен из РФ без VPN — в отличие от
  Anthropic/OpenAI/Groq.
- **Безопасность.** Нужен только scoped API Token (`cfut_`/`cfat_`), не
  Global API Key (`cfk_`). Токен храните в `.env`, а не в конфиге/git.

### 1.8. `cohere` — Cohere API (Compatibility API)

Cohere отдаёт OpenAI-совместимый endpoint, поэтому фабрика подключает его как
`openai_compatible`-провайдер — отдельный код не нужен.

Актуальные чат-модели (2026-11): `command-a-plus-05-2026` (новее),
`command-a-03-2025` (контекст 256k), `command-r-plus-08-2024`,
`command-r-08-2024`, `command-r7b-12-2024` (быстрее и дешевле). Все
мультиязычные, русский поддерживают.

Настройка:

1. Ключ — [dashboard.cohere.com/api-keys](https://dashboard.cohere.com/api-keys)
   (Trial или Production), в `.env`:

   ```bash
   COHERE_API_KEY=cohere_...
   ```

2. Провайдер уже прописан в `config/settings.yaml` и добавлен в `llm.fallback`
   после `dify`:

   ```yaml
   llm:
     providers:
       cohere:
         base_url: https://api.cohere.ai/compatibility/v1
         api_key_env: COHERE_API_KEY
         model: command-a-03-2025
   ```

3. Проверка. Из РФ `api.cohere.ai` отдаёт HTTP 403 (гео-блок), поэтому
   локальный `scripts/cohere_check.py` может не пройти — проверяйте из
   GitHub Actions: **Actions → cohere-check → Run workflow** (ключ берётся из
   `COHERE_API_KEY` в Secrets).

   Проверено 08.11.2026 из GitHub Actions: `GET /v1/models` вернул 200, все
   пять моделей ответили на тестовый чат (`command-a-03-2025` — «ОК»);
   workflow прошёл успешно. Той же ночью полный прогон завода в dry-run с
   обновлённым `settings.yaml` завершился успешно — конфиг совместим с
   облачным кодом.

Что важно знать:

- **Trial-ключ:** 1 000 запросов/мес и 20 запросов/мин на чат-модель
  ([rate limits](https://docs.cohere.com/docs/rate-limits)). При 2–3 вызовах
  на пост это ~330–500 постов/мес (~11–16/сутки) — Cohere разумно держать
  резервным провайдером, а не основным для 90 постов/сутки.
- **Production-ключ:** платный, лимиты выше (500 запросов/мин на Command A/R;
  для новых моделей — по договору с Cohere). Цена —
  [pricing](https://docs.cohere.com/docs/how-does-cohere-pricing-work).
- **Compatibility API** поддерживает `messages`, `temperature`, `max_tokens`,
  `response_format` (JSON Schema), `tools`; недоступны `n`, `logit_bias`,
  `service_tier` и Cohere-специфичные поля вроде `documents`.
- **JSON-режим.** Фабрика просит JSON промптом, `response_format` не
  требуется, поэтому structured outputs можно не настраивать.
- **Ключ.** Храните в `.env` и GitHub Secrets, не коммитьте. Если ключ
  засветился в чате/логах — перевыпустите его в кабинете Cohere.

## 2. Как выбрать модель под железо

Ориентируйтесь на объём RAM (для CPU) или VRAM (для видеокарты). Актуальные
модели 2026 года в квантовании Q4 занимают примерно:

| Модель | Размер на диске/в памяти | RAM/VRAM | Скорость на CPU |
|---|---|---|---|
| `qwen3.5:4b` | ~4 ГБ | 6–8 ГБ | быстро, базовое качество |
| `qwen3.5:9b` | ~7.6 ГБ | 12–16 ГБ | средне, хороший русский — дефолт завода |
| `hf.co/t-tech/T-lite-it-2.1-GGUF:Q4_K_M` | ~5 ГБ | 12–16 ГБ | русский стиль лучше, 32K контекст |
| `hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:q4_K_M` | ~6.5 ГБ | 10–16 ГБ | быстрее на CPU (MoE 1.8B active) |
| `qwen3.8:27b` | ~18 ГБ | 24 ГБ VRAM | GPU: секунды |

Практические рекомендации:

- **8 ГБ RAM, без GPU** → `extractive` или `qwen3.5:4b`; 9B будет тормозить и
  может не поместиться вместе с ОС.
- **16 ГБ RAM** → `qwen3.5:9b` на CPU — рабочий вариант для 2–3 постов за
  прогон (в 2026 это дефолт проекта).
- **Видеокарта 24 ГБ** → `qwen3.8:27b` заметно лучше по качеству.
- **Сервер без GPU / слабый ноутбук** → `extractive`; качество текста всё
  равно приемлемое, а стоимость и требования — нулевые.

Можно менять модель без переписывания кода: только `llm.ollama.model`.
Модели, которых нет в библиотеке Ollama, скачиваются прямо с Hugging Face:
`bash scripts/start-ollama.sh pull hf.co/<repo>:<quant>`.

## 3. Промпты и параметры

Параметры в `config/settings.yaml`:

```yaml
llm:
  timeout: 300        # сколько секунд ждать ответа модели (для локальной 9B — с запасом)
  max_tokens: 500     # максимум токенов в ответе
  temperature: 0.3    # 0 = стабильно/сухо, 1 = разнообразно
  ollama:
    num_ctx: 8192     # контекст Ollama; без него длинные статьи обрезаются
    think: false      # выключить «размышления» reasoning-моделей (быстрее в разы)
```

- Для новостного канала держите `temperature` в районе 0.2–0.4: меньше
  «фантазий».
- `max_tokens` 500 достаточно для поста 3–4 абзаца; для дайджеста с
  несколькими пунктами можно поднять до 1000–1200 (на локальной модели это
  дольше, поэтому для неё лучше 400–600).
- Промпты формируются внутри `content_factory/nlp/` и требуют от модели:
  писать по-русски, не выдумывать факты, ссылаться на источники, не
  копировать исходный текст дословно. Менять их можно в коде (см.
  [extending.md](extending.md)), но сначала проверьте результат.

## 4. Проверка выбранной LLM

```bash
./.venv/bin/python -m content_factory llm-test
```

Команда делает один тестовый запрос к выбранному провайдеру и печатает:
какой режим выбран, какая модель, ответ или понятную ошибку. С 2026-11 она
дополнительно печатает расход токенов за сутки и статистику кэша — по
сообщению «кэш: N попаданий» видно, что повторный запрос не тратит токены.

Что означают результаты:

| Вывод | Что делать |
|---|---|
| Ответ модели получен | всё хорошо, можно публиковать |
| «Ollama недоступна» | запустите Ollama, проверьте `base_url` и `ollama list` |
| «модель не найдена» | `ollama pull <модель>` или поправьте `llm.ollama.model` |
| ошибка авторизации GigaChat/YandexGPT | проверьте `.env`, срок действия ключа, лимит |
| Dify: `not_chat_app`, 401, `provider_quota_exceeded` | проверьте `llm.dify.app_mode` (chat/completion), `DIFY_API_KEY` и лимит Dify Cloud |
| таймаут | увеличьте `llm.timeout`, проверьте нагрузку на ПК |

Проверка не публикует постов и не тратит деньги, кроме минимального запроса
к облачному API.

## 5. Деградация в extractive

Если LLM отвечает ошибкой, не уложилась в таймаут или вернула пустой ответ,
конвейер **не падает**: он логирует проблему и генерирует пост в
extractive-режиме. В `runs.errors` будет запись, в отчёте — доля ошибок.
Поэтому даже с настроенной LLM канал продолжает работать при сбоях сети или
перезагрузке компьютера.

Причины частых ошибок:

1. Ollama не запущена после перезагрузки — добавьте её в автозапуск.
2. Модель не скачана.
3. Не хватает памяти — процесс Ollama убивается системой (OOM killer).
4. Облачный API: истёк токен/лимит, нет интернета.

## 6. Стоимость

- `extractive`, `ollama`, `openai_compatible` — **0 ₽**, только электричество.
- `gigachat` — 0 ₽ в пределах бесплатного лимита, дальше по тарифу
  провайдера.
- `yandexgpt` — пробный грант, дальше по тарифу.
- `dify` — бесплатный тариф Dify Cloud ограничен (сообщения/кредиты),
  дальше по тарифу Dify. Стоимость моделей внутри приложения зависит от
  того, чей ключ провайдера подключён в Dify.
- `cohere` — Trial-ключ бесплатный (1 000 запросов/мес, 20/мин), этого хватает
  на ~330–500 постов/мес (11–16/сутки); production-ключ — по тарифу Cohere.
- `cloudflare` — 10 000 neurons/день бесплатно (~100–150 вызовов), дальше
  $0.011 за 1 000 neurons.

Ориентир по трафику (2026-11): один пост — **2–3 запроса** в
оптимизированном режиме, ~3 100 токенов. 6 каналов × 15 постов = **90 постов
в сутки** → ~180–270 запросов и ~0,3 млн токенов в сутки. Это укладывается в
`daily_request_limit: 300`, а всё сверх лимита публикуется в бесплатном
`extractive`-режиме.

## 7. Экономия токенов (с 2026-11)

Токены стоят денег у облачных провайдеров и времени у локальных моделей.
В проекте включена экономия **без потери качества**: проверки ответов модели
не менялись, а при нарушении формата включается безопасный откат на прежнюю
схему.

| Механизм | Что делает | Где настраивается |
|---|---|---|
| **Кэш ответов** | точное совпадение промпта/модели → готовый ответ из `data/llm_cache.sqlite3`, модель не вызывается; попадание в кэш не тратит лимит запросов | `llm.cache`, `llm.cache_ttl_hours` |
| **Объединённый анализ** | резюме и тезисы одним запросом вместо двух: исходный текст уходит модели один раз | `llm.optimize.combined_analysis` |
| **Компактный заголовок** | заголовок переписывается по проверенному резюме (200–400 символов), а не по 4000 символов статьи | `llm.optimize.compact_headline` |
| **Учёт токенов** | реальный `usage` провайдера в `data/llm_tokens.json` (UTC), видно расход и экономию кэша | `llm-test`, лог после прогона |
| **Дневной лимит токенов** | после исчерпания завод уходит в `extractive` (полезно для платных API; локальные токены бесплатны) | `llm.daily_token_limit` |
| **keep_alive** | Ollama держит модель в памяти между прогонами демона (без повторной загрузки весов) | `llm.ollama.keep_alive` |

Пример настроек:

```yaml
llm:
  cache: true
  cache_ttl_hours: 168
  optimize:
    combined_analysis: true
    compact_headline: true
  daily_token_limit: 0        # 0 = без лимита
  ollama:
    keep_alive: 30m
```

**Замер на реальном сюжете** (12 762 символа текста, локальная `qwen3.5:9b`,
скрипт `scripts/token_economy_check.py`):

| Режим | Запросов | Промпт | Ответ | Всего |
|---|---|---|---|---|
| baseline (старые промпты) | 4 | 4 946 | 477 | **5 423** |
| optimized | 3 | 2 706 | 424 | **3 130** |

Итог: **−42% токенов и −1 запрос**, при этом валидаторы поста/анализа — OK,
количество тезисов и длина поста те же. Повторный прогон того же сюжета:
**0 токенов** (3 попадания в кэш, ~3 021 токен сэкономлен).

Проверить у себя:

```bash
./.venv/bin/python -m content_factory llm-test      # ответ + расход токенов за сутки
./.venv/bin/python scripts/token_economy_check.py   # замер baseline vs optimized
```

Отключить отдельные механизмы можно флагами `llm.optimize.*`, `llm.cache: false`
или `llm.cache_ttl_hours: 0`. Комбинированный анализ при «строптивой» модели
сам откатывается на два отдельных запроса — качество не падает.

## 8. Автопереключение при лимитах и гибрид по этапам

Завод больше не упирается в лимит одного провайдера: у каждого свой суточный
счётчик, а исчерпание автоматически переключает на следующего — вплоть до
платного DeepSeek. Когда кончаются все — остаётся бесплатный `extractive`,
посты продолжают выходить.

### Как это работает

- **Лимиты по провайдерам** (`llm.provider_limits`) — счётчики
  `data/llm_usage_<провайдер>.json`, сброс в 00:00 UTC. Исчерпали лимит →
  провайдер помечается недоступным, `FallbackLLMClient` берёт следующего.
- **Ошибки провайдера** (429/403/таймаут/пустой ответ) тоже помечают его
  недоступным до конца процесса — следующий вызов идёт к другому провайдеру,
  а не долбит исчерпанный.
- **Гибрид по этапам** (`llm.stage_routes`): анализ (резюме/тезисы) — на
  бесплатных моделях, генерация (заголовок/пост) — на качественном
  `deepseek-chat`. У каждого этапа своя fallback-цепочка.
- **Страховки:** `daily_token_limit: 700000` — общий суточный потолок токенов
  (после него extractive, чтобы платный API не разорил); `daily_request_limit`
  (общий жёсткий стоп на все запросы) по умолчанию `0` — выключен.

```yaml
llm:
  daily_request_limit: 0          # жёсткий стоп на всё, 0 = выкл
  daily_token_limit: 700000       # страховка от перерасхода платных API
  provider_limits:
    cloudflare: 150               # free ≈10 000 neurons/день
    cohere: 30                    # trial 1 000 запросов/мес
    ollama_cloud: 250             # кредиты Ollama Cloud
    deepseek_chat: 120            # платная генерация + запас
    gigachat: 60
    yandexgpt: 60
    dify: 20
    openrouter: 50
  stage_routes:
    analysis:
      provider: cloudflare
      fallback: [cohere, ollama_cloud, deepseek_chat, deepseek]
    generation:
      provider: deepseek_chat
      fallback: [ollama_cloud, cloudflare, cohere, deepseek]
```

### Порядок и стоимость

Типовой день (90 постов): анализ (~180 вызовов) уходит в бесплатные
Cloudflare → Cohere → Ollama Cloud; генерация (90 вызовов) идёт в
`deepseek-chat` — это порядка 100–200 тыс. токенов в сутки, то есть примерно
**$1–3 в месяц** по текущим ценам DeepSeek (цены меняются, проверяйте
[api-docs.deepseek.com](https://api-docs.deepseek.com/quick_start/pricing)).
Если дневной лимит DeepSeek исчерпан или API упал — работа продолжается на
Ollama Cloud/Cloudflare, затем на `extractive`.

### Как проверить

```bash
# общая цепочка (llm.provider + llm.fallback)
./.venv/bin/python -m content_factory llm-test
# маршрут этапа: анализ (дешёвый) и генерация (DeepSeek)
./.venv/bin/python -m content_factory llm-test --stage analysis
./.venv/bin/python -m content_factory llm-test --stage generation
```

В логах канала видно выбранные клиенты:
`Сюжетов: N; LLM анализ: cloudflare (доступна), генерация: deepseek_chat (доступна)`.
Счётчики лимитов кэшируются в GitHub Actions (`data/llm_usage_*.json`), поэтому
переживают перезапуски и не сбрасываются каждые 15 минут.
