## 4. Как поддерживать синхронизацию

`origin/main` двигают автоматические workflow-коммиты (алерты, дайджесты, пины) — поэтому перед
началом работы и перед push:

```bash
cd content-factory
git fetch origin
git status -sb            # если behind — git pull --ff-only
git pull --ff-only origin main
```

Правила, чтобы снова не разъехаться:

1. Не работать напрямую в `main`: ветка от свежего `origin/main` → PR/merge.
2. Долгие ветки перебазировать (`git rebase origin/main`) или merge не реже раза в день.
3. Не копить stash: правки — в ветку/коммит, а не в `git stash`.
4. Следить за `git worktree list` и `git worktree prune` (после удаления временных каталогов).
5. Слитые ветки удалять: `git branch -d <branch>` (или `git branch --merged main`).
