# План запуска и развития

Файл для тех, кто хочет не просто «поставить и забыть», а довести каналы до
рабочего состояния. Ниже — чек-лист первых 7 дней и дорожная карта улучшений.

## 1. Чек-лист первых 7 дней

### День 1. Установка и демо (1–2 часа)

- [ ] Python 3.9+ установлен (`python --version` / `python3 --version`).
- [ ] Скопирован `.env.example` → `.env` (пока можно пустой).
- [ ] Создан venv, установлены зависимости:
      `python -m pip install -r requirements.txt`.
- [ ] Запущено `python -m content_factory demo` — видно, что конвейер работает
      без сети и токенов.
- [ ] Открыт отчёт из демо (файл в `data/reports/`), понятно, как выглядят
      метрики.
- [ ] Прочитан [setup.md](setup.md) и [architecture.md](architecture.md).

### День 2. Бот и каналы

- [ ] В @BotFather создан бот, получен токен → `TELEGRAM_BOT_TOKEN` в `.env`.
- [ ] Созданы 6 каналов (или используются существующие).
- [ ] Бот добавлен **администратором** в каждый канал, право «Публикация
      сообщений» включено.
- [ ] Для каждого канала заполнены `TELEGRAM_CHAT_ID_*` (`@username` или
      `-100…`).
- [ ] `python -m content_factory channels` показывает 6 каналов и видит chat_id.
- [ ] `python -m content_factory sources check` — все источники отвечают (или
      понятно, какие нет).

### День 3. Первый dry-run

- [ ] В `.env` `CONTENT_FACTORY_DRY_RUN=true` (и в `settings.yaml`
      `dry_run: true`).
- [ ] `python -m content_factory run --channel all` — прошёл без ошибок.
- [ ] Посты появились в `data/outbox/`.
- [ ] `python -m content_factory preview --channel tech-ai` — текст читаемый,
      ссылки на источники есть, нет полных перепечаток.
- [ ] Проверены все 6 каналов: темы соответствуют, мусора нет.
- [ ] Поправлены `topics`/`exclude_keywords`/`sources` в
      `config/channels.yaml` по результатам.

### День 4. Первая реальная публикация

- [ ] `CONTENT_FACTORY_DRY_RUN=false` в `.env` (осознанно!).
- [ ] `python -m content_factory run --channel tech-ai` — пост появился в
      канале.
- [ ] Проверены ссылки, форматирование, хештеги.
- [ ] `data/factory.sqlite3` содержит запись в `publishes` с `ok=1`.
- [ ] Остальные каналы опубликованы по одному, с проверкой.

### День 5. Автономность

- [ ] Настроен автозапуск: systemd (Linux) или Планировщик заданий (Windows)
      — см. [operations.md](operations.md) и `scripts/`.
- [ ] `python -m content_factory report --days 1` строится после прогона.
- [ ] Проверено, что демон переживает перезагрузку.
- [ ] Настроен бэкап `data/factory.sqlite3` и `.env`.
- [ ] Логи пишутся в `data/logs/factory.log` и не растут бесконечно
      (ротация встроена: 2 МБ × 3 файла).

### День 6. Качество контента

- [ ] Прочитаны 10 последних постов каждого канала.
- [ ] Убраны источники, которые дают мусор/рекламу.
- [ ] Добавлены 1–2 источника, которых не хватает.
- [ ] Настроены тон (`tone`), эмодзи (`emoji`), CTA, хештеги.
- [ ] Проверены стоп-слова (`pipeline.banned_words`).
- [ ] Решено, нужна ли LLM: `python -m content_factory llm-test`; при желании
      подключена Ollama ([llm.md](llm.md)).

### День 7. Аналитика и порядок

- [ ] Построен отчёт за неделю: `report --days 7`, открыт `report.html`.
- [ ] Понятно, откуда подписчики (Bot API) и почему просмотров нет (ограничение
      Bot API).
- [ ] Изучены ошибки в `runs.errors`, повторяющиеся проблемы устранены.
- [ ] Настроено расписание слотов под аудиторию (МСК).
- [ ] Каналы стабильно публикуют 3 раза в день без ручного вмешательства.

## 2. Дорожная карта улучшений

Приоритеты: сначала то, что повышает качество и надёжность, потом — охват.

### Ближайшее (1–2 недели)

- [ ] **Медиа:** картинки к постам (собственные/лицензированные; без
      скачивания чужих фото «наугад»).
- [ ] **Модерация:** ручное подтверждение постов перед публикацией (команда
      `preview` уже есть; можно добавить «карантин» для спорных тем).
- [ ] **Больше источников:** Telegram-каналы как источники через Telethon
      (опциональная зависимость), веб-страницы без RSS.
- [ ] **Обратная связь:** учёт реакций/просмотров через Telethon или ручной
      импорт — чтобы понимать, какие темы заходят.
- [ ] **A/B:** два варианта заголовка/структуры поста, сравнение по реакциям.

### Среднесрочное (1–2 месяца)

- [ ] **VK и OK:** VK уже реализован; Одноклассники — по аналогии.
- [ ] **Дзен/сайт:** публикация на собственный сайт или в Дзен.
- [ ] **Мультиязычность:** английская версия каналов.
- [ ] **Кластеризация умнее:** эмбеддинги (локальная модель) вместо Jaccard
      при большом потоке.
- [ ] **Дашборд:** графики динамики в `report.html`.

### Долгосрочное

- [ ] **Мультиканальная сеть:** 10+ каналов с общим ядром и разными профилями.
- [ ] **Редакционная политика:** свои рубрики, авторские колонки, серии.
- [ ] **Монетизация:** реклама/подписка — с маркировкой и юридической
      проверкой ([legal.md](legal.md)).
- [ ] **Резервирование:** второй сервер/бэкапы с автоматической проверкой.

## 3. Метрики успеха

Смотрите в отчёт и базу; ориентиры «здорового» конвейера:

| Метрика | Норма | Где смотреть |
|---|---|---|
| Прогоны без ошибок | > 90% | `runs.errors` в отчёте |
| Опубликовано/сгенерировано | > 80% | `publishes` / `posts` |
| Дубли постов | ~0 | повторные темы в ленте |
| Доля источников-мусора | < 20% | вручную по ленте |
| Подписчики | растут | `metrics.subscribers` |

Если публикаций больше 3 в день на канал — проверьте, что не срабатывают
лишние слоты; если постов нет совсем — смотрите `runs.errors` и
релевантность тем.

## 4. Что важно не забыть

- Не запускать два демона на одной базе SQLite.
- Не коммитить `.env` и `data/`.
- Не публиковать полные тексты чужих статей.
- Не выдавать аналитику за факты.
- Просматривать первые недели работы вручную.
